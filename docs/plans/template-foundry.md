# Plan — Template Foundry (generative logo templates)

Status: approved by Dave 2026-07-13. Live personalized gallery, generative
from primitives (no static template library), lives on dashboard AND as an
editor panel.

## Concept

Kittl-style "Templates → Logos", but every card is generated locally as a
real `LogoDocument` from `{archetype × font pairing × palette × motif ×
seed}`. The user types their brand name (+ optional tagline) once; every
card re-renders live with it. Shuffle regenerates with new seeds. Inserting
a card materializes a fully editable vector document — no baked images
anywhere.

Vocabulary: these are **Template Proposals** generated by the **Foundry**;
inserting one creates/extends a **Logo Document** (CONTEXT.md terms).

## Architecture

### New package: `packages/foundry` (`@openlogo/foundry`)

Pure, DOM-free, depends only on `@openlogo/core` types. Fully unit-testable.

- `generate(input): LogoDocument` where input =
  `{ brandName, tagline?, archetypeId, vibe?, seed }`.
  Deterministic: same input → identical document (stable node ids derived
  from the seed).
- **Seeded PRNG** (small local implementation, e.g. mulberry32). Card
  identity = `{archetypeId, seed}` so a card can be re-materialized later.
- **Archetypes** (v1, ~6): each a layout recipe with parameter ranges the
  PRNG samples from:
  1. `wordmark` — type-only, tracking/weight/case play, optional underline
     or divider motif.
  2. `stacked-badge` — brand over tagline inside rectangular/shield badge,
     rules and stars.
  3. `circular-seal` — text on arc (uses core `onPath` TextPathAttachment)
     around a center motif or monogram.
  4. `monogram` — 1–2 initials, large, enclosed in circle/diamond/shield
     frame, brand name beneath.
  5. `cartouche` — brand in a decorative frame (banner/laurel), retro feel.
  6. `lockup` — abstract geometric mark + brand name beside/below.
- **Ingredient tables** (curated, in-package data):
  - Font pairings by vibe, referencing families that exist in the editor's
    font catalog (packages/editor/src/lib/font-catalog.ts BUILTIN_FONTS
    first; catalog families allowed but the gallery must preload them
    before showing cards that use them).
  - Palettes: ~12 curated (bg + primary + accent), tagged by vibe.
  - Motifs: small geometric path-data library authored in-package (stars,
    laurels, banners, bursts, rules, crowns, simple marks). Pure SVG path
    strings + viewBox metadata; no external assets, no licensing risk.
- **Vibes** (filter chips): e.g. minimal, classic, retro, streetwear, elegant,
  playful. A vibe filters archetype weighting + pairings + palettes.

### Editor integration (`packages/editor`)

- **Preview rendering**: generated documents render to inline SVG via the
  existing SVG export path (svg-fonts/text handling) — no CanvasKit needed
  on the dashboard. Webfonts for pairings load via existing FontFace paths;
  gallery shows a card only when its fonts are ready (skeleton until then).
- **Dashboard**: "Start from a template" section/tab in DashboardView —
  brand name + tagline inputs, vibe chips, shuffle button, responsive card
  grid, per-card palette-swap chips on hover. Clicking a card creates a new
  Logo Document from the generated doc (artboard sized to the archetype)
  and enters the editor.
- **Editor panel**: slim left panel (Kittl-like) with the same gallery;
  inserting adds the generated nodes as a group into the active artboard
  of the current document (one undoable command), reusing brand name from
  the document name as default.
- **Reproducibility**: store nothing new in IndexedDB for v1; a card's
  `{archetypeId, seed, vibe, palette}` travels in memory only. (Favorites/
  pinning is a later phase.)

## Phases

1. **Foundry package**: PRNG, ingredient tables, motif library, 6
   archetypes, `generate()`, exhaustive unit tests (determinism, node
   validity via core parse, text-on-path attachments well-formed).
2. **Dashboard gallery**: SVG preview pipeline + font preloading, brand
   input, vibe chips, shuffle, create-document flow.
3. **Editor panel + polish**: insert-into-document command, palette-swap
   chips, per-card "open in new document" alternative, perf pass
   (generation + preview render budget: card grid of 24 in <100ms
   generation, previews streamed as fonts arrive).

## Risks / invariants

- Quality control: archetype parameter ranges must be conservative —
  bad-but-valid layouts are the failure mode. Ranges reviewed per archetype
  with rendered fixtures (test writes SVG snapshots for eyeballing).
- Font readiness: never show a card in a fallback font; skeleton until the
  pairing's faces are loaded.
- Text-on-arc correctness depends on core `onPath` behavior — validate via
  parseDocument in tests.
- Determinism: same seed must survive refactors within a minor version;
  tests pin fixture outputs.
- Do not touch Design Mate; do not regress dashboard startup budget
  (foundry package lazy-loaded with the gallery view).
